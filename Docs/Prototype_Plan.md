## 1. 제출용 핵심 경험

한 줄: **"붕어빵 한 판이 구워질 때마다 가게가 눈에 보이게 커지는 방치형 성장 게임."**

벽돌 주식회사가 주는 "단순 행동 → 파괴의 쾌감 → 성장 속도 체감 → 환생" 흐름을, 파괴 대신 **굽는 쾌감**(반죽·속·지글지글·뒤집기·완성의 리듬, 터지는 입자와 소리)으로 바꾼다. 같은 장르의 골격은 유지하고 테마 교체로 얻는 차별점을 네 가지로 보여준다.

1. **스테이지 = 붕어빵 종류.** 기본→팥→슈크림→치즈→황금 붕어빵으로 올라갈수록 굽는 시간이 길고 값이 크다(원작의 벽돌 종류·체력에 해당). 점포 규모와 배경도 함께 커져 "다음 붕어빵이 보고 싶은" 동기를 만든다.
2. **굽기 5단계 + 알바 종류.** 한 판은 반죽→속→굽기→뒤집기→완성을 거친다. 5명의 알바(반죽·앙금·화덕·뒤집기·포장)가 각 단계를 맡고, 숙련도를 올리면 그 단계 시간이 줄어든다(원작의 무기 강화=데미지 상승 → 굽는 시간 단축).
3. **직접 굽기 콤보 vs 알바 자동화.** 처음엔 단계 버튼을 박자 맞춰 눌러 굽고(제때 이어 누르면 콤보 수익 최대 ×2), 알바를 채용하면 자동으로 굽는다. 직접 굽기는 불 게이지를 채워 '황금 불판' 순간 가속을 일으키는 *선택적 개입*이며 방치만으로도 진행은 된다.
4. **프랜차이즈 환생.** 황금 붕어빵 단계에 닿으면 본사로 환생해 영구 배수와 포인트를 얻고, 2회차가 눈에 띄게 빨라진다. 로드맵(공장~우주)은 환생 후 열릴 다음 장으로 보여준다.

제출 때 보여줄 것(검증 질문): ① 첫 3분 안에 직접 굽기→알바 고용→자동 수익을 이해하는가 ② 강화 한 번이 수치와 화면에 모두 드러나는가 ③ 환생 후 2회차가 빨라졌음을 느끼는가 ④ 재접속 시 오프라인 정산이 이해되는가.

## 2. 플레이 흐름

### 2.1 세션 흐름 (첫 실행)

| 시간 | 플레이어 행동 | 시스템/화면 |
|---|---|---|
| 0:00 | 앱 진입 | 리어카 + 손님 한 명. 굽기 버튼(단계 버튼) 하나만 강조, 5단계 칩(반죽·설탕·굽기·뒤집기·완성) 표시, 투자 카드는 잠금(회색) |
| 0:10 | 단계 버튼을 단계가 찰 때마다 탭 | 단계마다 소리·입자·의성어, +8 팝업, 매출 ₩25 도달 → 알바 채용 카드 활성 (깜빡임) |
| 0:30 | 알바 채용 | 알바 캐릭터 등장, 자동 굽기 시작. 문구 "알바가 자동으로 굽는 중" |
| 1:00 | 알바 탭에서 알바 숙련(반죽·앙금·화덕·뒤집기·포장) 강화, 레시피 개발 | 해당 단계 시간 `0.60초→0.50초`가 줄어드는 것이 수치와 칩 게이지에 보임. '병목' 단계 표시 |
| 1:30~3:00 | 진행도 바 100% | '새 메뉴 개발 → 팥 붕어빵' 버튼 활성 → 붕어빵 종류와 점포가 전환 (화면 변화 1) |
| 3~20분 | 슈크림→치즈→황금 붕어빵 | 단계마다 §3 연출. 설비(자동화) 구매, 레벨 한도 상승 |
| 약 18~22분 | 황금 붕어빵 + 누적 매출 목표 도달 | 본사 탭 '프랜차이즈 개점' 활성, 예상 획득 포인트 표시 |
| 환생 | 확인 팝업 → 환생 | 리어카로 되돌아가되 영구 배수, 알바 1명 시작. 2회차 약 9~11분에 같은 지점 도달 |

### 2.2 핵심 루프

```
5단계 굽기(직접 콤보/알바 자동) → 매출 → 투자(알바 숙련·알바 채용·레시피·설비) → 굽는 시간 단축·처리량 증가
      ↑                                                       ↓
 프랜차이즈 환생 ← 황금 붕어빵 + 누적 매출 목표 ← 새 메뉴 개발(붕어빵 종류·화면 변화)
```

### 2.3 화면 구성 (시안 기준, 하단 4탭: 매장/알바/성장/본사)

시안(1080×1920 기준 y좌표)을 그대로 따른다.

| 영역 | 내용 | 비고 |
|---|---|---|
| 헤더 (y 0~140) | 타이틀 '붕어빵 주식회사', 설정 버튼 | 설정: 사운드 on/off, 저장 초기화, 오프라인 정산 기록 |
| 매출 카드 (y 140~290) | 현재 매출, 초당 매출 | 숫자 증가 시 부드러운 롤링 |
| 진행도 바 (y 310~460) | `n / 11 단계명`, 다음 단계명, 진행 % | 5단계에서는 환생 진행도로 전환 (§2.4) |
| 가게 장면 (y 500~1140) | 단계별 점포·알바·손님·붕어빵 | §3 |
| 굽기 버튼 (y 1100~1250) | 지금 해야 할 단계 `2. 팥 넣기!  +N` + 안쪽 5단계 칩(차오르는 게이지, 가득 차면 '!') | 불 게이지는 버튼 아래 얇은 바. 단계가 안 찼을 때 탭하면 무시되고 칩이 흔들림 |
| 안내 문구 | '알바가 자동으로 굽는 중 · 단계마다 탭하면 매출 추가', 콤보 중에는 `콤보 4 · 수익 ×1.15` | 상황별 문구 교체 |
| 오늘의 투자 (y 1350~) | 카드 2장(가장 효율 좋은 투자: 알바 숙련·알바 채용·레시피·설비 중) + 새 메뉴 개발/프랜차이즈 띠 | 시안의 '오늘의 투자'는 가장 효율 좋은 2개를 보여주는 구조로 해석 |
| 하단 탭 (y 1800~) | 매장 / 알바 / 성장 / 본사 | 아래 표 |

- **매장 탭**: 위 표 전체. 가장 자주 보는 화면.
- **알바 탭**: 알바 종류 5행(반죽·앙금·화덕·뒤집기·포장 알바). 행마다 맡은 단계, 레벨, `0.60초 → 0.50초`(현재→다음 시간), 가격 칩. 가장 느린 단계에 '병목' 표시, 위에 `한 판 N초`.
- **성장 탭**: 알바 채용(인원), 레시피 개발, 자동화 설비 카드. 각 카드에 현재 레벨 → 다음 레벨 효과, 비용, 한도 표시. '오늘의 투자'는 알바 숙련까지 포함한 모든 투자 중 효율(회수 시간) 최상위 2개를 보여준다.
- **본사 탭**: 프랜차이즈 환생 패널(예상 포인트, 영구 업그레이드 3종), 로드맵(6~11단계 잠금 카드), 통계(누적 매출, 플레이 시간, 환생 횟수), 저장/불러오기 상태.

### 2.4 프랜차이즈 띠와 진행도 바 상태

- 1~4단계: 진행도 = `현재 매출 / 다음 메뉴 개발 비용`. 시안의 64%는 포장마차에서 12,480 / 19,500이라는 가상 예시이며 실제 비용은 §4.2 표를 따른다.
- 5단계(황금 붕어빵): 바 문구를 `5 / 11 황금 붕어빵 · 다음: 공장 (준비 중)`으로 하고, 바 값은 `이번 회차 누적 매출 / 환생 목표`로 전환한다. 100%가 되면 프랜차이즈 띠가 강조된다.
- 프랜차이즈 띠: 1~4단계 `대형가게에서 해금 →`(잠금), 5단계 진행 중에는 `프랜차이즈 개점 n%`, 목표 달성 시 `프랜차이즈 개점 (+N 포인트)`.

## 3. 단계별 화면 변화 (스테이지 = 붕어빵 종류)

붕어빵 종류가 스테이지를 구분한다. 점포는 같이 커지는 배경 연출이다.

| 단계 | 붕어빵 | 속 재료 | 굽는 시간 배율 | 점포 |
|---|---|---|---|---|
| 1 | 기본 붕어빵 | 설탕 | ×1.00 | 리어카 |
| 2 | 팥 붕어빵 | 팥 | ×1.25 | 포장마차 |
| 3 | 슈크림 붕어빵 | 슈크림 | ×1.50 | 구멍가게 |
| 4 | 치즈 붕어빵 | 치즈 | ×1.75 | 동네가게 |
| 5 | 황금 붕어빵 | 황금 앙금 | ×2.00 | 대형가게 |

붕어빵 외형은 기본·팥·슈크림 스프라이트를 쓰고 치즈는 슈크림 스프라이트에 치즈색을 입히며 황금은 황금 스프라이트다. 속 넣기 입자 색도 속 재료를 따른다.

공통: 배경 하늘과 바닥 색은 시안의 따뜻한 크림·주황 톤을 기본으로 하고 단계가 올라갈수록 채도를 올리고 요소를 추가한다. 모든 단계는 **같은 레이아웃 슬롯**(점포 / 알바 / 손님 / 붕어빵)을 써서 구현 부담을 줄인다. 상세 리소스는 Resource_Manifest.md.

| 단계 | 점포 | 점포 연출 | 알바 / 손님 | 붕어빵·설비 | 진입 연출 |

## 4. 숫자 · 강화 · 환생 · 저장 설계

### 4.1 생산 공식

```
판당 수익  BV  = V[단계] × 레시피배수 × 프랜차이즈배수 × 설비배수(1.6^설비수)
알바배수   m(Lv) = (1 + 0.20×Lv) × 1.5^floor(Lv/10)           ← 5명의 알바가 같은 공식을 쓴다
단계 시간  T_i = 기본시간_i × 붕어빵 시간배율[단계] / m(알바_i 숙련Lv)   (반죽 0.6 · 속 0.6 · 굽기 1.2 · 뒤집기 0.3 · 완성 0.3, 합 3.0초)
한 판 시간 T   = T_dough + T_filling + T_bake + T_flip + T_finish
레시피배수 RC  = (1 + 0.25×레시피Lv) × 2^floor(레시피Lv/10)
자동 초당  AUTO = 알바 인원 × BV / T
직접 굽기  단계 1회 탭 = BV × 콤보배수  (단계가 준비된 뒤 0.6초 안에 이어 탭하면 콤보+1, 늦으면 1부터)
콤보배수       = 1 + 0.05 × (min(콤보, 21) − 1)               ← 최대 ×2
초당 매출  = AUTO (+ 황금 불판 중이면 ×3)
```

- 한 번 탭이 단계 하나이므로 한 바퀴(5탭)가 한 판이다. 단계 시간이 차기 전의 탭은 무시된다(초당 8회 상한도 유지).
- `V[단계]` = 8 / 75 / 720 / 7,350 / 80,000. 기존 8 / 60 / 480 / 4,200 / 40,000에 붕어빵 시간 배율(1 / 1.25 / 1.5 / 1.75 / 2)을 곱한 값이라, 시간 배율을 넣어도 `BV÷T`(초당 수익)의 단계 간 비율이 개정 전과 같다.
- 시안 카드 문구 '한 판 수익 +25%'와, 알바 숙련 한 레벨당 해당 단계 시간이 `1/(1+0.2×Lv)`로 줄어드는 것(예: 반죽 0.60초→0.50초)은 위 선형 증가분과 일치시킨 것이다. 10레벨 마일스톤(속도 ×1.5, 수익 ×2)은 UI에 `Lv 10에서 ×2` 로 예고 표시한다.
- 표시 규칙: 판당 수익 팝업 `+N`은 TAP 또는 알바 한 판 결과를 그대로 보여준다.

### 4.2 단계 표

| 단계 | V (판당 기본) | 시간 배율 | 알바 인원 한도 | 알바 숙련·레시피 레벨 한도 | 설비(자동화) | 다음 메뉴 개발 비용 |
|---|---|---|---|---|---|---|
| 1 기본 붕어빵 | 8 | ×1.00 | 2 | 10 | — | ₩30,000 |
| 2 팥 붕어빵 | 75 | ×1.25 | 4 | 20 | 자동 뒤집개 | ₩3,000,000 |
| 3 슈크림 붕어빵 | 720 | ×1.50 | 6 | 30 | 반죽 디스펜서 | ₩4억 |
| 4 치즈 붕어빵 | 7,350 | ×1.75 | 8 | 40 | 컨베이어 화덕 | ₩600억 |
| 5 황금 붕어빵 | 80,000 | ×2.00 | 10 | 50 | 포장 라인 | 공장은 로드맵 → 환생 |

- 레벨 한도는 단계가 오르면 해금된다(확장의 이유를 만든다). 설비는 단계 진입 후 구매하는 1회성 항목으로 `×1.6`, 비용 = `0.25 × 해당 단계 진입 비용`. 설비는 1단계에는 없다.
- 초기 알바 인원은 0명. 첫 알바는 단계 버튼 탭으로 번 ₩25로 채용한다(수동→자동의 학습 순서).

### 4.3 구매 비용

| 항목 | 비용 공식 | 비고 |
|---|---|---|
| 알바 k번째 채용 (k=0부터) | 25 × 2.4^k | 단계별 인원 한도 |
| 알바 숙련 Lv L→L+1 (알바 종류 i) | 40 × (기본시간_i ÷ 3초) × 1.5^L → 반죽·속 8, 굽기 16, 뒤집기·완성 4 × 1.5^L | 레벨 한도. 5명을 같은 레벨까지 올리는 총비용 = 개정 전 화덕 비용(40×1.5^L) |
| 레시피 개발 Lv L→L+1 | 60 × 1.55^L | 레벨 한도 |
| 설비 | 0.25 × 단계 진입 비용 | 단계당 1개, ×1.6 |

비용은 매출이며 소비 후 매출은 감소한다. 환생 전까지 매출 외 소프트/하드 재화는 없다(범위 통제).

### 4.4 황금 불판 (직접 개입 보상)

- 유효한 탭(단계 수행) 1회당 불 게이지 +8 (0~100). 마지막 탭 후 1.5초가 지나면 초당 −10 감소(굽기 단계가 1.2초라 유지 시간을 늘림).
- 100 도달 시 8초 동안 **황금 불판**: AUTO와 탭 수익 모두 ×3. 종료 후 게이지 0으로 초기화하고 쿨다운은 없다.
- 탭이 잦아도 이득은 한정(약 +50% 내외)이고, 방치 플레이도 환생까지 도달하도록 목표 시간을 잡는다(§4.8).
- 접근성 대안: 설정에서 '자동 황금 불판' 기본 off. 별도 구현 없이 연출 강도만 off 가능.

### 4.5 환생 — 프랜차이즈

| 항목 | 값 |
|---|---|
| 해금 조건 | 5단계 도달 + 이번 회차 누적 매출 ≥ ₩10조 (1e13) |
| 획득 포인트(FP) | `floor(5 × sqrt(회차 누적 매출 / 1e13))` — 최초 달성 시 5 |
| 영구 효과 | 판당 수익 × (1 + 0.20 × 총 FP) |
| 환생 시 초기화 | 매출, 단계(→1), 알바 인원, 알바 숙련 5종·레시피 레벨, 설비, 게이지, 콤보 |
| 환생 시 유지 | FP, 프랜차이즈 업그레이드, 환생 횟수, 총 통계, 설정 |
| 시작 보너스 | 알바 1명으로 시작 (프랜차이즈 업그레이드 '본사 교육'으로 확장) |
| 환생 권장 표시 | 예상 FP가 현재 보유 FP의 50% 이상일 때 '지금 개점하면 +N' 강조 |

프랜차이즈 업그레이드(FP 소비, 영구) — 3종, 각 5레벨:

| 이름 | 효과 | 비용(FP) |
|---|---|---|
| 본사 교육 | 환생 후 시작 알바 +1명/레벨 | 3, 5, 8, 12, 18 |
| 비법 레시피 | 레시피 한도 전 단계 +5 | 4, 6, 9, 14, 20 |
| 야간 영업 | 오프라인 보상 한도 +1시간/레벨 | 3, 4, 6, 9, 13 |

P0에서는 영구 배수만 구현하고, 3종 업그레이드는 P1로 둔다.

### 4.6 오프라인 정산

- 종료·복귀 시각 차이 `elapsed`를 구한다. 음수(시계 되돌림)는 0으로 처리.
- 정산 = `AUTO(저장 당시 초당 매출) × min(elapsed, 한도) × 0.5` (탭·황금 불판은 제외). 기본 한도 2시간, 야간 영업으로 최대 +5시간.
- 단계 확장, 구매, 환생은 오프라인 중 일어나지 않는다. 복귀 시 팝업 `+N 매출 (자리 비운 시간 hh:mm)` 한 번 표시, 광고 2배 버튼은 비활성 모형(D6).
- 한도를 넘긴 시간은 버리고 '한도 도달' 문구를 보여준다.

### 4.7 저장 (localStorage)

- 키: `bungeoppang.save.v1` (직전 저장은 `bungeoppang.save.v1.bak`에 보관).
- 저장 구조(JSON, 숫자는 문자열이 아닌 number):

```
{ "v":1, "savedAt":<epoch ms>, "stage":1~5, "money":n, "runRevenue":n, "totalRevenue":n,
  "alba":n, "fireLv":n(굽기=화덕 알바), "doughLv":n, "fillingLv":n, "flipLv":n, "finishLv":n, "recipeLv":n, "equip":n, "fp":n, "rebirths":n,
  "fpUp":{"train":n,"recipe":n,"night":n}, "heat":0, "playSec":n,
  "settings":{"sound":true}, "stats":{...} }
```

- 알바 숙련 4종 필드는 구저장에 없으면 0으로 읽는다(저장 버전 `v` 유지). 단계 진행·콤보는 저장하지 않는다.
- 저장 시점: 5초 주기 자동 저장, 구매·새 메뉴 개발·환생 직후, `visibilitychange(hidden)`·`pagehide`.
- 로드: 키 없음 → 새 게임. JSON 파싱 실패 또는 `v` 불일치 → `.bak` 시도 → 그래도 실패하면 새 게임 + 설정 탭에 한 줄 경고. 필드 누락은 기본값으로 채우고 NaN/Infinity/음수는 보정한다.
- 접근 불가(사생활 보호 모드 등) 환경에서는 메모리만 사용하고 설정 탭에 '저장 불가' 표시. 예외로 게임이 멈추지 않는다.
- 저장 초기화는 설정에서 2단계 확인 후 두 키를 삭제하고 새로 시작한다.
- 보안(변조 방지)은 프로토타입 범위 밖이며 문서에 한계로만 기록한다.

### 4.8 목표 시간 (시뮬레이션 추정치, 인게임 미검증)

탐욕 봇(회수 시간 최소 항목을 즉시 구매, 알바 숙련 5종 포함)을 TS(`tests/bot.ts`)로 돌린 결과. 시간 단위는 분. 직접 굽기는 '탭 시도/초'로 모델링하며 단계가 안 찼으면 무시된다.

| 구간 | 탭 시도 0.5/s | 탭 시도 2/s | 숙련 플레이(준비되면 즉시 탭) | 개정 전 기획 목표(0.5/s) |
|---|---|---|---|---|
| 5단계(황금 붕어빵) 도달, 1회차 | 14.0 | 5.5 | 3.1 | 16 |
| 환생 목표 도달, 1회차 | 18.5 | 8.0 | 5.2 | 22 |
| 환생 목표 도달, 2회차 (FP 5) | 9.2 | 4.0 | 2.6 | 11 |

- 합격 기준: 0.5/s 봇이 개정 전 목표와 ±25% 이내(현재 약 −15%로 통과). 벗어나면 §4.2의 비용·시간 배율만 조정(공식은 건드리지 않음).
- 2탭/초 목표(18분)는 여전히 충족하지 못한다. 단계 버튼은 단계 시간이 찰 때만 유효해 개정 전보다 빠른 플레이가 더 유리하다. 결정 대기 항목으로 남긴다.
- 인게임 실측은 하지 않았다(`Docs/Code_Handoff.md` §6, §5).

### 4.9 큰 수 처리

- 프로토타입 범위의 최대 매출은 1e14 안팎, 환생 후 2회차도 같은 자릿수라 double 정밀도 한계(약 9e15) 이내다.
- 표기: `1,000 미만 정수 / 만·억·조·경 단위 소수점 2자리 / 1e20 이상은 지수 표기`. 예 `12,480`, `3.20억`, `1.50조`.
- 로드맵(6~11단계)에서 1e30 이상이 필요해지는 시점에 `BigNum{m,e}`로 교체한다. 로직이 모두 `Num` 별칭을 쓰게 해 교체 범위를 한 파일로 한정한다.

## 6. 검증 기준

### 6.1 자동 검증 (node 테스트, 에디터 불필요)

1. 포맷: 0, 999, 12,480, 1억, 3.2e8, 1.5e12, 1e20 표기가 §4.9 규칙과 일치.
2. 공식: 레벨 0/1/10/25 입력에서 SP·RC·BV가 §4.1 손계산과 일치.
3. 구매: 비용 부족 시 불가, 한도 초과 시 불가, 구매 후 매출 감소량이 비용과 같다.
4. 확장: 비용 충족 시에만 단계 +1, 5단계에서 확장 불가.
5. 환생: 목표 미달 시 불가. 달성 시 FP 계산, 초기화 항목·유지 항목이 §4.5와 일치.
6. 오프라인: elapsed 음수 → 0, 한도 초과 → 한도, 보상이 AUTO×0.5×시간.
7. 저장: 저장→로드 왕복 동일. 깨진 JSON, 누락 필드, NaN, `v` 불일치에서 새 게임 또는 `.bak` 복구가 예외 없이 동작.
8. 봇 시뮬: §4.8 목표 시간 ±25%.
9. 굽기 5단계: 한 판 시간=5단계 합(스탯 0이면 3초×배율), 알바 숙련이 해당 단계만 줄임, 단계 순서·준비 전 탭 무시·콤보 증가/끊김·초당 8회 상한, 붕어빵 종류별 속 재료 이름·시간 배율, 구저장 호환(알바 숙련 필드 0).

### 6.2 수동 검증 (Cocos 프리뷰 + 웹 빌드)

1. 최초 실행 첫 10초 안에 굽기 버튼 외 조작이 필요 없고, 첫 알바 고용까지 안내 문구로 유도된다.
2. 1~5단계 전환 시 §3의 붕어빵 종류·점포·손님 변화가 눈에 보이고, 전환 중 입력이 꼬이지 않는다.
3. 시안 대비 레이아웃 차이: 헤더·매출 카드·진행도 바·굽기 버튼·투자 카드·탭의 위치와 문구가 일치(스크린샷 비교, 의도적 차이는 기록).
4. 새로고침·탭 닫기 후 재접속에서 상태 복원, 오프라인 팝업 1회 표시.
5. 환생 후 2회차 1단계가 알바 1명으로 시작하고 FP 배수가 상태에 보인다.
   단계 버튼을 박자 맞춰 누르면 콤보와 연출·소리가 터지고, 일찍 누르면 무시된다(소리는 브라우저에서 첫 터치 뒤에 난다).
6. 6~11단계 로드맵은 잠금 상태이며 누르면 '준비 중' 안내만 나온다. 실제 진입 경로가 없다.
7. 모바일 폭(약 390×844)과 데스크톱 브라우저 양쪽에서 UI 잘림이 없다.
8. 5분 방치 시 프레임이 안정적이고 콘솔 에러가 없다(웹 빌드 기준).
9. localStorage 차단 환경에서 게임이 멈추지 않고 '저장 불가'를 표시한다.

### 6.3 제출 시 표기할 사항

- 플레이 링크(웹 빌드)와 한 줄 조작 안내, 구현 범위(1~5단계 + 환생, 6~11 로드맵), 본인 판단과 AI 사용 범위, 리소스 출처(Resource_Manifest의 출처 기록 기준), 알려진 제한(광고·결제·변조 방지 없음, 밸런스는 봇 추정 중심).
- 검증하지 않은 항목을 검증했다고 쓰지 않는다. 벽돌 주식회사를 직접 플레이한 것처럼 쓰지 않는다.
